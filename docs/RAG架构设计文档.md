# RAG架构设计文档

本文档详细记录了 MindScribe（灵辑）系统的检索增强生成（RAG）架构设计，包括当前的实现逻辑和未来的演进规划。

## 一、 现有设计：结构优先的精确切片（Structure-First RAG）

当前系统采用“结构优先”的策略，利用 Markdown 文档的层级结构进行精确切片。

### 1.1 核心逻辑

系统将 Markdown 文档视为一个层级化的树状结构，利用标题标记（`#` 和 `##`）作为天然的语义边界。

1.  **意图识别与参数提取**：
    *   LLM 识别用户意图（如 `SUMMARY`）。
    *   提取关键参数：`doc_title`（文档标题）和 `target_chapter`（目标章节）。
    *   例如：用户问“第三章讲了什么”，提取 `target_chapter="第三章"`。

2.  **结构化切片（Structure-Based Slicing）**：
    *   **定位**：使用正则表达式（如 `^## 第X章`）在文档中定位章节的起始位置。
    *   **边界识别**：向下扫描寻找下一个同级标题（`##`）或父级标题（`#`）作为结束位置。
    *   **提取**：提取起始和结束位置之间的所有文本作为上下文。

3.  **全文兜底（Full-Text Fallback）**：
    *   如果用户未指定章节，或文档没有章节结构，系统回退到全文处理模式。
    *   直接将整个文档内容作为上下文发送给 LLM。

### 1.2 优缺点分析

*   **优点**：
    *   **高精度**：提取的内容具有完美的语义边界，不会截断句子或段落。
    *   **低成本**：不需要向量数据库，不需要 Embedding 计算，纯文本处理速度快。
    *   **可解释性强**：检索逻辑清晰直观，易于调试。

*   **缺点**：
    *   **依赖规范**：高度依赖文档的 Markdown 结构。如果文档是“流水账”或无结构笔记，切片逻辑失效。
    *   **长文档限制**：对于无结构的超长文档，全文兜底可能触发 LLM 的 Token 限制。

## 二、 未来设计：混合增强策略（Hybrid RAG Strategy）

针对无结构文档（如零散笔记、数学题集）的场景，未来将采用 **“写入时重组” + “语义向量检索”** 的组合策略。

### 2.1 方案一：写入时重组（The "Librarian" Approach）—— 强化现有的智能归类

**核心理念**：既然用户不写章节，AI 就帮他写。在数据**写入**阶段就强制结构化，从而复用现有的“结构优先”检索优势。

*   **工作流程**：
    1.  **用户输入**：例如“这道微积分题很难...”
    2.  **语义分析**：系统后台分析这条笔记的语义（数学 -> 微积分）。
    3.  **自动归档**：系统自动在文档中寻找或创建 `## 微积分` 或 `## 错题集` 章节。
    4.  **结果**：原本零散的笔记被自动组织成了结构化的 Markdown。

*   **价值**：
    *   保持文档的可读性和有序性。
    *   无需修改现有的检索逻辑，直接复用结构化切片能力。
    *   文档越写越有序，形成良性循环。

*   **挑战**：
    *   需要处理用户坚持“流水账”记录习惯的情况，避免过度干预。

### 2.2 方案二：语义向量检索（The "Search Engine" Approach）—— 标准 RAG 引入

**核心理念**：承认文档的无序性，通过高维向量空间来寻找相关性。

*   **工作流程**：
    1.  **颗粒度切片**：不再按章节切，而是按“条目”或“段落”切分。
        *   例如：对于数学题，将“题干+解答”作为一个 Block。
    2.  **Embedding**：将每个 Block 转化为向量，存入轻量级向量库（如 Chroma 或本地 FAISS）。
    3.  **检索**：当用户问“上次那道关于极限的题”时，计算余弦相似度，提取最相关的 Top-K 个 Block。

*   **价值**：
    *   对“零散笔记”极其有效，能精准定位大海捞针的信息。
    *   解决了无结构文档无法精确检索的问题。

*   **挑战**：
    *   引入了向量库的复杂度。
    *   可能丢失上下文信息（如题目与前后复习计划的关联）。

### 2.3 实施路线图

1.  **短期（Smart Classification 2.0）**：
    *   利用现有的智能归类功能，尽可能引导内容结构化。
    *   优化 Prompt，提高归类的准确性和用户接受度。

2.  **长期（Local Vector Store）**：
    *   对于无法归类的“流水账”，在浏览器端或本地建立轻量级索引。
    *   实现混合检索：优先尝试结构化检索，失败后回退到向量检索。
